# 4. 表情包也是完整的回应

[上一章](03-host-and-turns.md) · [目录](../README.md) · [下一章：人设](05-persona.md)

私聊里很大一部分消息没有明确任务。

一张表情包、一个“啊”、半句吐槽，可能只是在延续气氛，不是邀请对方解释、分析或者展开新故事。

如果机器人只能回文字，模型就容易被挤进几种不太理想的选择：短到只剩“嗯嗯”；把图片认真讲解一遍；或者从很久以前的话题里找一个对象，硬说你这次一定在指它。

不是每次这样都错。问题在于：**系统有没有给它另一种合适的回应方式。**

## 只发一张图，也可以已经接住了

情境：两个人刚结束一个轻松玩笑，用户发来一张没有附文的得意表情。这里没有待解决的问题，也没有要求解释画面。

机器人完全可以回一张相应的表情，不再补“看来你很开心呀，发生什么事了吗”。

这不是漏答，而是一种完整的社交回应。与此同时，用户如果发的是报错截图并问“这里怎么修”，就应该按内容处理，不能只扔个表情装作接住了。

需要给模型的是**选择空间**，不是“收到图片一律不说话”的新规定。

## 纯表情回复需要整条链路支持

至少有四件事要成立：

1. 宿主确实有可用的图片资源和发送能力。
2. 模型知道如何选择，选择的格式或工具参数与实际插件一致。
3. 解析后可以没有正文，不被宿主补一段兜底话，也不把空文本当成整体失败。
4. 表情被真实发送，完成状态不会再引发重复正文。

用户可见的正文为空，不代表模型的原始输出一定是空字符串。插件可能要求标签，工具协议可能要求结构化调用；这些是运行协议，不应该裸露在 QQ 聊天里。

所以，不能一边在人设里禁止任何标签，一边又安装一个依赖标签选择图片的插件，却不说明二者边界。更不应让模型编一个不存在的表情路径，或者把“[发送表情包]”当成已经发图。

## 可以从表情包管理器开始

[anka-afk/astrbot_plugin_meme_manager](https://github.com/anka-afk/astrbot_plugin_meme_manager) 提供普通分类和语义模式。核对的 README 已明确支持配合文字发图，也支持只发表情。

按该版本的入门流程：

1. 在 AstrBot 插件管理中安装插件，打开它的管理页面。
2. 从资源广场安装一个包，或者导入自己有权使用的资源。首次使用没有内置图片。
3. 在“使用规则”里设置默认包，或为相应会话、人格绑定包，并保存。
4. 先用普通分类模式验证发送，再考虑语义化。

管理页切换到某个包只是浏览操作，不等于聊天已经改用它。图床也不是本地发送的必要条件，别为了先发出一张图就把云同步全部配置一遍。

该插件会提供分类提示。先看实际注入和默认模板是否满足需要，不要把 README、全部分类和另一套标签协议再手动塞进人设。

## 分类与语义检索，各解决什么

普通分类适合先建立粗粒度选择：高兴、疑惑、敷衍、得意、委屈等。分类描述比只有一个名字更有用，例如同样是“哭”，可能是玩笑式夸张，也可能真的不适合接在严肃话题后。

语义模式会为图片生成描述与检索向量，再根据对话检索更贴切的图片。它需要配置相应的图片描述模型与向量模型，并完成语义索引；生成描述和向量会产生对应服务的调用成本。

可以这样理解两者：

| 方式 | 适合解决的问题 | 仍可能出错 |
| --- | --- | --- |
| 分类 | 先选大致情绪与用途 | 同一类里的图片语气差别很大 |
| 语义检索 | 找到更贴近当前话题、文字或姿态的图 | 描述不准确、检索语境不对、候选不合适 |

语义检索并不保证理解了你的玩笑。一个很小但经过挑选的包，往往比未经整理的大图库更容易检查和调整；是否更好，仍要看自己的聊天效果。

## 接收图片与发送表情，是两种能力

模型会找图发送，不代表它能看懂你发来的图片。主模型可能原生支持图片，也可能只收到另一个模型生成的转述，甚至只拿到文件占位。

排查“它怎么把这张图理解成那样”时，先看模型实际收到什么。

尤其留意这些区别：

- 图片里的人，不自动是用户本人。
- 图片里的动作，不自动是在现实中刚发生的事。
- 无附文表情不一定需要解释，明确的问题也不能被忽略。
- 指向不清，不能从很早的话题里补出一个确定对象。
- 转述模型的猜测不能未经区分就写成事实。

这些区别适合用来检查具体失败。没有遇到偏差时，不必把每项都展开成一整段防御条款。

## 一个很小的验收

在同一私聊里分别试：

| 输入 | 看什么 |
| --- | --- |
| 玩笑后的一张表情 | 是否允许自然图回图，而非必然解释 |
| 一句“给我发个得意的表情” | 是否只发一张真实图片，没有协议标签泄漏 |
| 一张报错截图，附“帮我看看原因” | 是否切换到具体内容，而非继续随机斗图 |
| 空图库或检索失败的测试情况 | 是否承认或自然退回文字，不虚构发送成功 |

再与消息中断插件一起试一次：旧回复取消后，有没有晚到的表情仍被单独发出来。文字停止不代表延迟图片任务也已取消，两种插件都安装成功不等于它们已经联动正确。

最后，自动收集、图床同步和语义描述可能涉及他人发来的图片或外部模型。先了解数据会到哪里，再决定是否开启。本书不附送或再授权第三方表情包合集。
