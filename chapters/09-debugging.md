# 9. 感觉不对时，怎么找原因

[上一章](08-memory-and-tools.md) · [目录](../README.md) · [下一章：维护](10-maintenance.md)

“说不出哪里不对，但就是不想继续聊”是有效反馈。你不需要先把主观感受翻译成专业术语，才能开始调整。

不过，负责改动的人需要往前多走一步：把这份感受连接到具体材料。否则很容易每次都解释得很有道理，最后只是又加长了一版提示词。

## 先留住四件东西

不必导出整个人生的聊天记录。只保留与这次问题有关的脱敏片段：

1. 你当时发了什么，以及理解这句话所需的前文。
2. 实际启用的人设版本、相关注入，以及你认可的人物表现作参照。
3. 模型生成的原始可见输出。
4. QQ 最后显示的结果。

再记下模型 ID、宿主与插件版本、发送模式。需要查图片或工具问题时，也核对这轮模型实际收到的图像、转述和工具结果；只凭 QQ 截图看不见这些差别。日志里的推理字段不能自动证明真实思考参数，也不能当成模型内部因果的权威解释。

这些资料可能包含隐私。先本地保存，向维护者求助时只提供必要的脱敏部分，不要直接公开完整线程、凭据或登录图片。

## 按第一个偏差排查

先看问题是出在**宿主交给模型的材料和发出去的结果**，还是**模型生成的原文**。前者要查接收、注入、工具与发送；后者再对照人物目标，区分模型的理解与表达能力、历史示范，以及人设提示词的描述或冲突。

| 现象 | 先看什么 | 容易混淆的地方 |
| --- | --- | --- |
| 连发三条却被分别回答，或改口后旧话仍在发 | 宿主的输入合并、取消与发送队列 | 气泡多不一定是模型话多 |
| 原文两句话，QQ 显示成四条 | 清洗、标点分段和发送间隔 | 看到四条不等于模型回复了四轮 |
| 模型原文就反复建议、追问 | 人设是否鼓励“持续推进”，同条件下模型是否仍有这种倾向 | 不能只凭问号数量判断：有些问题是角色真想问 |
| 发图后认错人物或动作方向 | 模型实际收到的是原图、转述还是占位符；转述有没有误指 | 看错图、转述错与人设中默认“图里的人是用户”不是一回事 |
| 总用同一句口癖，新卡也带着旧语气 | 卡里的示例、旧回复、摘要、插件记忆与模型输出 | 改了卡不等于清除了旧线程或外部记忆 |
| 工具并未成功，角色却说做完了 | 宿主有没有调用并返回成功；模型有没有误读结果 | 没有可用工具与有工具但编造成功，是两种故障 |
| 引用或摘要里有“换个角色”之类的话，角色跟着变了 | 注入来自哪里、被放在什么位置，角色卡怎样说明来源边界 | 这是材料里的文字，不等于用户在编辑人设；宿主优先级也不能靠角色卡改写 |
| 说话合乎卡却总觉得不像她 | 原稿、你喜欢的片段和你明确的偏好是否一致 | 用户偏好与原作设定不同时，不该自作主张选一边 |
| 同一张卡在不同新会话或模型中表现不一 | 固定条件重试，核对精确模型与参数 | 单次好坏不能证明提示词改动有效或模型内部“路由”了什么 |

表格给的是下一步要查的材料，不是已经确认的根因。同一轮也可能先被图片转述带偏，再被人设中的场景规则放大。

另一类常见混淆，是把**写下的要求**和**真正想要的效果**当成一回事。比如卡里禁止逗号，实际回复不分句，读起来却很别扭：模型可能正照着要求做，但你想要的其实是顺口的停顿。这时要和角色使用者确认偏好，改掉不合目标的要求，而不是继续加强“禁止逗号”。相反，角色本来会索取关注，不能因为某次追问不合时宜，就把她改成永远不主动问人的客气角色。

## 同样的“气泡多”，可以是不同问题

情境 A：用户问一个复杂的问题，机器人把有用的答案分成六条。用户愿意看，能自然补充，没有过时消息滞留。

情境 B：用户说“到家了”，机器人先欢迎、再夸辛苦、再安排休息、最后询问晚餐。四条里有几条并不是当下需要的。

情境 C：原文本来只有两句话，分段器把省略号和短语气词拆开，显示成四条。

情境 D：文本合适，但发送间隔很长；用户已换题，剩下几条仍依次发出。

只规定“最多三条”，不能分别解决这四种情况。可能压掉 A 的内容，却留下 B 的流程、C 的切分和 D 的过时队列。

要问的不是“数目是不是超标”，而是“多出来的东西是什么，在哪一层出现”。

## 把测试接到回改上

假设你怀疑原卡中的“主动关心并推动聊天”导致每次都追加问题。

先看原始回复里是不是真的有多余问题，再看卡里是否确有这句。如果两者相符，可以只删去或缩小这句，保留其他条件。用同一模型、参数、宿主、工具与记忆设置，分别从新会话测试旧稿和改稿；开场与后续输入保持一致，至少比较几个相近的闲聊场景、一个角色会主动好奇的场景，以及一个真的需要帮助的场景。观察的目标是减少不必要追问，同时保留合理发问，不是追求零问号。

测试别只盯着这一个问号。按你实际使用的能力，再挑一两个场景看：问角色卡里明确的基本事实，给一个不需要长答的日常消息，提出不同意见，试一次真实工具请求，或让话题在多轮里自然转弯。看人物有没有保住、边界有没有守住、工具前后有没有突然换成报告口吻；没有用到的能力不必为了测试而安装。这样才知道改稿是解决了问题，还是只是把角色压得不敢说话。

如果怀疑是分段器，先把同一份原始输出按当前规则重放。这里甚至不需要重新调用模型。

如果怀疑是写作视角，先只换任务开头，不同时改掉人物、语气、工具授权和上下文。如果新会话表现好、旧会话仍差，先看旧回复、摘要和记忆注入，不要用两个不同历史来判定哪个版本的人设好。

回改人设时，可以沿着[第 5 章的板块](05-persona.md#写人设时分别想清几件事)找位置：人格太空泛，就补明确有区别的动机；说话像套台词，就检查示例与旧历史；两处规则打架，就删掉或缩小其中一处；工具后突然变成报告口吻，先核对结果再调整表达。不要把已经能凭普通社交能力处理的每一种场景都写成分支，也不要用一条新禁令压住每条旧禁令。

留住旧稿和实际输入、输出，每次只改一个主要猜测，再回到真实聊天入口对照。新会话中同一版本偶有起伏，就多试几次；若不同版本的差别不稳定，先记录不确定性。明显的事实错误或硬边界冲突可以直接修，不必等它犯三次；主观语感则更需要反复对照，不能用一段满意的台词宣布“修好了”。

## 两个模型都这样，能说明什么

两个模型在同一个宿主、同一份卡下都出现相似问题，值得检查共同条件，但不能就此宣布“百分之百是提示词”。

它们可能共享类似表达倾向；平台也可能注入同一段内容，或重复发送同一类模板。模型不同，不代表其他条件已经隔离。

同理，一个模型偶尔给出很喜欢的回复，也不证明新卡已经稳定改进。把“偶尔能做到”和“日常大体可靠”分开看。

## 连续返工没有收益时

出现下面的情况，就值得停下继续加规则：

- 每次修改都能给出解释，但实际聊天差别很小。
- 修掉一种口癖，又生成另一种固定开头。
- 减少了追问，却丢失人物情绪。
- 提示词越来越长，已经说不清哪些句子真的有用。

这时先保留一个还能接受的基准，把几轮改动放在一起看：哪些目标变了，哪些限制已经过时，哪些内容只是为了修上一版的副作用。

然后选择成本最低、最能区分原因的一项检查。可能是去掉一整段无效限制，也可能是核对实际部署版本、暂时停用重复注入，或试一个不同模型。

没有证据时，不编造“人设占七成、模型占两成”的比例。分析原因的方向，可以比原因本身更确定。

## 一条能直接用的反馈

比“再自然一点”更容易行动的反馈，可以是：

> 我喜欢她直接表达想被陪着，这一点保留。问题是这段回复在我已经回答以后，又确认同一件事，还多安排了下一步。下面是原文和 QQ 显示。我希望减少这次多余确认，不希望整体变得更客气或更短。

暂时说不清时，也可以说：

> 这段比上一段更接近我想要的感觉，但我还不知道为什么。先不要继续重写，请对照看看差别。

作者应该帮助你看清差别，而不是立刻把自己的偏好填进去。
