# 9. 感觉不对时，怎么找原因

[上一章](08-memory-and-tools.md) · [目录](../README.md) · [下一章：维护](10-maintenance.md)

“说不出哪里不对，但就是不想继续聊”是有效反馈。你不需要先把主观感受翻译成专业术语，才能开始调整。

不过，负责改动的人需要往前多走一步：把这份感受连接到具体材料。否则很容易每次都解释得很有道理，最后只是又加长了一版提示词。

## 先留住四件东西

不必导出整个人生的聊天记录。只保留与这次问题有关的脱敏片段：

1. 你当时发了什么，以及理解这句话所需的前文。
2. 实际启用的人设版本和相关注入。
3. 模型生成的原始可见输出。
4. QQ 最后显示的结果。

再记下模型 ID、宿主与插件版本、发送模式。日志里的推理字段不能自动证明真实思考参数，也不能当成模型内部因果的权威解释。

这些资料可能包含隐私。先本地保存，向维护者求助时只提供必要的脱敏部分，不要直接公开完整线程、凭据或登录图片。

## 按第一个偏差排查

| 现象 | 优先检查 | 暂时别做什么 |
| --- | --- | --- |
| 连发三条，被分别回答三次 | 输入事件与消息合并 | 先加“不要话多” |
| 已经改口，旧气泡仍在发 | 旧轮次取消与发送队列 | 只降低输出字数 |
| 一段原文变成很多气泡 | 清洗、标点、正则与分段延迟 | 把截图气泡当模型调用数 |
| 只有图片时也解释一大段 | 模型收到的图片或转述、纯表情能力 | 给所有图片统一静默 |
| 总用同一个语气词 | 示例、历史、自定义注入和模型偏好 | 马上扩充口癖轮换表 |
| 每次关心都带一串问题 | 原稿是否鼓励“持续推进”、模型原文 | 全面禁止角色发问 |
| 说工具做成了但后台没有 | 调用、参数、返回及投递状态 | 用更自然的台词掩盖失败 |
| 新会话好，旧会话越来越怪 | 旧示范、摘要、记忆与压缩 | 只改新卡却不检查旧注入 |
| 换了人设还带着旧口癖 | 旧线程回复和已注入的摘要 | 只在旧线程继续叠加禁令 |

这张表是排查入口，不是已经确认的根因。一个问题可能同时有几层因素。

## 同样的“气泡多”，可以是不同问题

情境 A：用户问一个复杂的问题，机器人把有用的答案分成六条。用户愿意看，能自然补充，没有过时消息滞留。

情境 B：用户说“到家了”，机器人先欢迎、再夸辛苦、再安排休息、最后询问晚餐。四条里有几条并不是当下需要的。

情境 C：原文本来只有两句话，分段器把省略号和短语气词拆开，显示成四条。

情境 D：文本合适，但发送间隔很长；用户已换题，剩下几条仍依次发出。

只规定“最多三条”，不能分别解决这四种情况。可能压掉 A 的内容，却留下 B 的流程、C 的切分和 D 的过时队列。

要问的不是“数目是不是超标”，而是“多出来的东西是什么，在哪一层出现”。

## 一次只验证一个主要猜测

假设你怀疑原卡中的“主动关心并推动聊天”导致每次都追加问题。

可以只删去或缩小这句，保留其他条件，然后比较几个相近的闲聊场景和一个真的需要帮助的场景。观察的目标是减少不必要追问，同时保留合理发问，不是追求零问号。

如果怀疑是分段器，先把同一份原始输出按当前规则重放。这里甚至不需要重新调用模型。

如果怀疑是写作视角，先只换任务开头，不同时改掉人物、语气、工具授权和上下文。

这些检查不保证立即找出原因，但能让失败也提供一点信息。

## 两个模型都这样，能说明什么

两个模型在同一个宿主、同一份卡下都出现相似问题，值得检查共同条件，但不能就此宣布“百分之百是提示词”。

它们可能共享类似表达倾向；平台也可能注入同一段内容，或重复发送同一类模板。模型不同，不代表其他条件已经隔离。

同理，一个模型偶尔给出很喜欢的回复，也不证明新卡已经稳定改进。把“偶尔能做到”和“日常大体可靠”分开看。

## 连续返工没有收益时

出现下面的情况，就值得停下继续加规则：

- 每次修改都能给出解释，但实际聊天差别很小。
- 修掉一种口癖，又生成另一种固定开头。
- 减少了追问，却丢失人物情绪。
- 提示词越来越长，已经说不清哪些句子真的有用。

这时先保留一个还能接受的基准，把几轮改动放在一起看：哪些目标变了，哪些限制已经过时，哪些内容只是为了修上一版的副作用。

然后选择成本最低、最能区分原因的一项检查。可能是去掉一整段无效限制，也可能是核对实际部署版本、暂时停用重复注入，或试一个不同模型。

没有证据时，不编造“人设占七成、模型占两成”的比例。分析原因的方向，可以比原因本身更确定。

## 一条能直接用的反馈

比“再自然一点”更容易行动的反馈，可以是：

> 我喜欢她直接表达想被陪着，这一点保留。问题是这段回复在我已经回答以后，又确认同一件事，还多安排了下一步。下面是原文和 QQ 显示。我希望减少这次多余确认，不希望整体变得更客气或更短。

暂时说不清时，也可以说：

> 这段比上一段更接近我想要的感觉，但我还不知道为什么。先不要继续重写，请对照看看差别。

作者应该帮助你看清差别，而不是立刻把自己的偏好填进去。
