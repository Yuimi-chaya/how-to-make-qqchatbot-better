## 这些副本做了什么处理

保留文章正文、署名与已有声明；去掉博客 frontmatter 和封面引用，把标题恢复成 Markdown 标题。站点专用的代码框、图文容器转换为普通 Markdown；五篇文章之间的链接改为本地副本；正文图片全部改为 `../assets/` 下的相对路径。

没有下载博客封面。部署文中 30 张配图、陪伴随笔中 2 张配图一并收录；其他三篇在该快照中没有正文图片。图片文件保持原始字节，来源、尺寸和哈希见[导入清单](../sources/import-manifest.json)。

这不是逐字节原稿归档，也不是替原文悄悄修订观点。可通过各篇顶部的固定提交链接阅读原始文件。

## 旧经验与本书不同的地方

### 第一人称人设文章

“首轮路由到某种理解”是作者当时解释表现波动的说法，不是已验证的模型内部机制。不能从这一表述断言后续表现已被首轮锁定。

气泡数、正反例选择，以及“多数问题归为描述质量或规则冲突”的取舍，也不能作为通用结论。本书分别看宿主、模型、上下文与人设；作者能解释规则，不代表目标模型会按设想执行。

原文限制“我查了一下”等表述，是当时的沉浸偏好。本书不把自然说明能力或结果一概禁止，更不能为保持人设虚构工具成功。原文中的身份措辞也不能用于覆盖真实平台规则。

### 写作视角文章

它解释了作者采用这一方向的理由，但不是第一人称与写作视角的受控优劣证明。书中允许保留传统写法，借鉴方法不等于必须迁移任务身份。

工具与提醒还要依据实际授权和宿主能力理解。已经存在适用的持续授权时，不必每次重新确认；支持相对延迟，也不必先要求绝对日期。

### 插件开发文章

附带 Skill 是当时的开发参考，不是新版本框架的官方规范。字段、嵌套配置、事件生命周期、插件页面、打包和安装方式，需要按目标版本核对。

文中关于插件市场 AI 参与比例的表述没有在本书中做统计核验，不作为行业数据引用。

### 部署文章

不要照图复制 token、账号、二维码、服务器地址或 API Key；也不要按旧表格开放全部端口。当前教程选择同容器网络、受限管理入口和明确认证。镜像标签与模型名以实际项目和提供商为准。

历史截图中包含第三方界面及凭据相关画面。本地收录不表示凭据已经失效、图片已通过隐私审计或第三方素材可以自由再分发。

### AI 陪伴随笔

这是个人经历与情感表达，不是 LLM RP 起源、产品史或模型能力的考证。涉及早期模型和产品演变的叙述，不作为本书技术结论的依据；一次提醒成功也不代表长期调度可靠。
